# 中国惊奇先生 · 漫画阅读 APK

一个只为《中国惊奇先生（神鬼七杀令）》单部漫画服务的 Android 阅读器。打开即读、滑屏翻页、自动阅读、自动追更、记住进度。整个项目从零逆向站点接口到打包签名，只用 JDK + Android SDK 命令行工具完成，无 Gradle、无第三方依赖。

**直接下载**：[`release/jingqi-v1.3.0.apk`](release/jingqi-v1.3.0.apk)（137 KB，Android 6.0+，签名 SHA-256 见下）

---

## 功能

- **免目录直达**：打开即显示封面信息 + 大按钮"开始阅读/继续阅读"，一键进入上次看到的那张图
- **滑屏阅读**：上下滑动连续看图，图片满屏宽、懒加载 + IntersectionObserver 预加载
- **翻话手势**：章末点右侧（或"本章完"整块）→ 下一话；章首点左侧 → 上一话；点中间 → 显隐顶栏
- **进度记忆**：精确到"第几张图"，退出重开自动跳回（含图片渐次加载的二次位置校正）
- **章节目录**：全部 1839 话，从旧到新排列，"最新 / 上次"角标定位
- **自动追更**：启动时联网刷新目录（与内置目录同构去重排序），新话追加到末尾
- **防抖**：翻话加载期间忽略重复点击，快速双击不会连跳两话
- **自动阅读 / 自动翻页**：顶栏"自动"按钮一键开启，按"剩余距离 ÷ 剩余时间"自适应匀速滚动，读完自动进入下一话，可连续翻话不停；到最新一话自动停止
- **每章自定义阅读时间**：章末"本章阅读时间：X 秒（默认/自定义）·点按设置"直接修改；目录长按章节同样可设，设过自定义的章节显示 `Xs` 角标；长按顶栏"自动"可改全局默认（默认 60 秒/章，5~3600 秒）

## 开发过程实录

### 1. 站点逆向

目标站点为 qTcms 架构漫画站（`gugu5.cc` 桌面站 + `m.yueman1.cc` 移动站镜像）：

- **章节列表**：详情页 DOM 一次性内嵌全部章节（`history_in('标题','链接')` 格式），无需翻页接口
- **图片地址**：章节页 JS 变量 `qTcms_S_m_murl_e` = Base64(所有图片 URL 以 `$qingtiandy$` 拼接)，本地解码即可
- **防盗链**：无（任意 UA/Referer 均可访问图床），WebView 直接加载

### 2. 三个坑与修复（都是实测踩出来的）

#### 坑 1：章节顺序 ≠ 链接 ID 顺序

站点目录的 DOM 顺序才是真实阅读顺序：新→旧→最早无编号话（"传说""王小二进城"等 26 话）→ 尾部 32 个"补传替换"条目。若按图片 URL 里的资源 ID（pid）排序，会把最早的话排到中间。

更隐蔽的是**尾部补传条目是同一话的替换版本**，其中 15 个是字符错误且图片服务器已下线的死链（如"977 起死话生"，正确版是"977 起死回生"）。处理方式：按章节号去重 + 逐话下载首图验证可用性 + 保留可用版本，最终从 1871 条目精确到 **1838 话**（正好等于最新话号，一章不缺）。站点目录还存在局部乱序（1150 插在 1149 后面隔了 5 项），用章节号稳定排序修正。

见 `build_catalog2.py`。

#### 坑 2：WebView 换章保留滚动位置

在章末点击进入下一话后，`loadDataWithBaseURL` 加载的新页面**沿用了上一章的滚动偏移**——用户停在新章节的尾部，像"总是显示最后一个"。修复：页面加载完成后强制 `scrollTo(0,0)` 两次（120ms / 700ms，防止图片加载撑开页面后再偏移）；只有"继续阅读"才恢复到 `last_img`。

#### 坑 3：图床返回带广告烙印的图片（核心坑）

用户截图反馈：漫画画面上叠了一层"包子漫画 APP"二维码广告。排查链：

1. 电脑上直接下载同一话图片 → **干净的**，排除"所有图带广告"
2. 对比不同 UA / Referer / `X-Requested-With` 请求头 → 字节完全一致，排除请求特征触发
3. 读站点自己的阅读器 JS（`show.20131212.js`），找到这行：

```js
v = v.replace(/https:\/\/s[12]\.[^\/]+(\/scomic\/)/g, 'https://p8.taoman.cc$1');
```

**真相**：接口返回的 `s1/s2.bzcdn.net` 是带广告注入的旧图源（每张多约 60KB 的广告图层），站点网页端自己会改写到 `p8.taoman.cc` 干净源。只有执行这条改写规则的客户端才能拿到干净图。修复只需一行（见 `MainActivity.java` 中 `replaceAll`），副收益是图片体积小约 27%。

> **2026-10-26 后续**：站点随后撤掉了 bzcdn 的广告层（实测两源逐字节一致），而 Cloudflare 的 `p8.taoman.cc` 在部分国内移动网络不可达——v1.1.2 / v1.2.0 在真机上表现为"图片打不开"。v1.2.1 改为：接口原始地址（bzcdn）为主源，taoman 改写地址与 s1/s2 互换作逐级兜底，单图加载失败自动切换下一源；章节页请求遇站点间歇性 WAF 403 自动重试 3 次。

### 3. 无 Gradle 打包

纯命令行构建链（`build.ps1`）：

```
aapt2 compile → aapt2 link(生成 R.java) → javac(-source 8) → d8(dx)
→ aapt add classes.dex → zipalign → keytool 生成密钥 → apksigner 签名
```

单 Activity、纯系统控件（ListView + WebView），APK 仅 132 KB。

## 本地构建

```powershell
# 需要 JDK 17 + Android SDK（build-tools 34 / platform android-34）
# 脚本内通过 SDK_ROOT 常量定位，按需修改
powershell -ExecutionPolicy Bypass -File build.ps1
# 产物: jingqi.apk
```

`build_catalog2.py` 可在站点更新后重建内置目录（需要 Python 3.8+）。

## 项目结构

```
├── build.ps1                  # 一键构建（aapt2 → javac → d8 → zipalign → 签名）
├── build_catalog2.py          # 从站点页面重建章节目录（去重 + 验活 + 排序）
├── gen_icon.py                # 生成启动图标（Pillow）
├── apk/
│   ├── AndroidManifest.xml
│   ├── src/MainActivity.java  # 全部逻辑：目录解析 / WebView 阅读器 / 自动阅读 / 进度管理
│   ├── assets/catalog.json    # 内置 1839 话目录（旧→新）
│   └── res/                   # 图标、主题、网络安全配置
└── release/jingqi-v1.3.0.apk  # 已签名安装包
```
